# MultiBit generation: xorBits + MultiBitsConsCheck

Implements Protocol `MultiBits` (Section 5 of the paper: `xorBits`,
`MultiBitsConsCheck`) for two similar-size moduli `q`, `t`, using an
auxiliary large prime `Q` for the consistency check. This is the missing
piece for a real `modconv1-preproc`: the trusted-dealer stand-in used in
`modconv1_online.mpc`'s preprocessing can, in principle, be replaced by a
call to this to get a securely-generated mask instead of a dealer-supplied
one (see "How this connects to ModConv1" below).

## Files

- `Programs/Source/xorbits.mpc` — standalone `xorBits` for one modulus:
  Input + a bitness check + the sequential `u xor v = u+v-2uv` combination.
  Useful on its own and as the reference for what `multibits_small.mpc`
  and `multibits_large.mpc` both do internally.
- `Programs/Source/multibits_small.mpc` — `xorBits` plus the "side `i`"
  half of `MultiBitsConsCheck`, run inside a small modulus (`q` or `t`).
- `Programs/Source/multibits_large.mpc` — `xorBits` plus the "side `ell`"
  half of `MultiBitsConsCheck`, run inside the auxiliary large modulus `Q`,
  checked against *all* the small domains at once.
- `Scripts/xorbits_gen_inputs.py` — test-input generator for
  `xorbits.mpc` alone.
- `Scripts/multibits_gen.py` — orchestrates the full pipeline: computes
  all of `MultiBitsConsCheck`'s parameters, generates the shared per-party
  input bits, compiles and runs all three domains (`q`, `t`, `Q`) via
  `shamir-party.x`, and performs the final comparison.
- This file.

## Why three domains for two moduli

`MultiBitsConsCheck` checks a small modulus `q_i` against the *largest* one
`q_ell`, and needs `q_ell` to be exponentially larger:
`q_ell >= 2^(tau_ell+1) * q_i` (see the protocol for where `tau_ell` comes
from). Our `q` and `t` were deliberately chosen to be *similar* size (per
the earlier scoping decision), so neither can play that role for the
other. The paper's own remark covers this: borrow an auxiliary prime `Q`,
large enough to check both `q` and `t` against, and discard
`shared{b}_Q` once the check passes. `multibits_gen.py` picks `Q`
automatically (smallest prime satisfying the precondition for the given
`kappa`).

## What's real vs. simplified here

Real, unsimplified:
- **Input.** Every bit each party contributes is a genuine MP-SPDZ
  `sint.get_input_from`, i.e. real secret-sharing over the network.
- **The XOR combination `u+v-2uv`.** Uses MP-SPDZ's native `sint`
  multiplication directly — this already *is* a secure multiplication
  protocol (Beaver triples under Shamir), not a simulation of one.
- **`func_Abb.RandomBit`.** `multibits_large.mpc` uses
  `sint.get_random_bit()`, MP-SPDZ's native `bit` instruction — real
  preprocessing under the compiled protocol, not hand-rolled.
- **The coin-tossed challenge `r`.** Generated by every party inputting a
  uniform mask and revealing the sum — the same "at least one honest
  contribution makes the sum uniform" argument used for opening `y` in
  `modconv1_online.mpc`.
- **`MultiBitsConsCheck` itself**, including the sacrificed-block
  bookkeeping (`tau_i`, `R_i`, disjoint blocks), the two openings `z` and
  `z~`, and the abort condition — implemented as specified, not
  approximated.
- **The final comparison of `z mod q_i` against `z~ mod q_i`.** Genuinely
  needs no MPC once both sides are open (see the protocol's own proof);
  done here as plain Python in the orchestrator, which is the accurate
  place for it — nothing is "faked" by moving it out of an .mpc script.

Simplified, and documented as such:
- **`CheckedInput` is replaced by a per-bit check.** The paper's
  `CheckedInput` is a batched, FLIOP-based proof that an entire input
  vector consists of bits, with O(1) amortized communication. Here, every
  single bit's bitness is checked individually via
  `open(x*(1-x)) == 0, abort otherwise` — real, sound, and leaks nothing
  beyond "this was a bit" (see the code comment in `xorbits.mpc` on why
  each check must be opened individually rather than summed first), but
  costs one multiplication and one opening per bit instead of one FLIOP
  proof per batch. For the batch sizes used in these tests this is a
  performance simplification only, not a correctness or security gap.
- **Threshold/corruption model.** Everything here inherits whatever
  threshold `shamir-party.x` is configured with; no changes were made to
  MP-SPDZ's own security parameters beyond the statistical security
  parameter `kappa` that this protocol introduces.

## How this connects to ModConv1

`modconv1_online.mpc`'s preprocessing currently comes from a trusted
dealer (`modconv1_dealer.py`). The real `modconv1-preproc` (paper,
Section 4.1) instead samples the mask via MultiBits and a secure
comparison. What's built here supplies exactly the MultiBit part: a
family of bits shared simultaneously over `q` and `t` (with the
consistency check ensuring no party can make the two domains disagree
about the underlying bit). Turning this into a full replacement for
`modconv1_dealer.py` still needs the secure `Compare` protocol referenced
by the paper's `modconv1-preproc` (used to derive the interval-index
corrections `u_i` from the mask `m` without any party learning `m`) —
that piece hasn't been read or implemented yet; see the paper's
`compare.tex` for its specification.

## Running it

```
# Full pipeline: N parties, n real MultiBits, moduli q and t, auxiliary Q
# picked automatically to satisfy the consistency check's precondition
# for the given kappa (statistical security bits, default 16 for fast
# testing -- use 40 for anything resembling a real deployment).
Scripts/setup-ssl.sh <N>   # once per party count
python3 Scripts/multibits_gen.py <N> <n> <q> <t> --kappa 40 --seed 1
```

Prints the derived parameters (`n_prime`, `tau`/`R` per domain, `Q`'s bit
length), each domain's revealed *test-only* prefix (for sanity-checking
that `q`, `t` and `Q` agree, and that they match the plaintext-computed
expected XOR — a real caller never reveals this), the per-repetition
`z` vs `z~` comparison, and a final `PASS`/`FAIL` verdict.

`xorbits.mpc` can also be run standalone (single modulus, no consistency
check) via `Scripts/xorbits_gen_inputs.py` — see that script's docstring
and the compile-time example in `xorbits.mpc`'s header comment.

## Verified behaviour

- Correctness: for every run below, the revealed prefixes from `q`, `t`
  and `Q` are identical to each other and to the plaintext XOR of the
  raw input bits.
- Soundness (negative test): deliberately making one party's contribution
  to a single domain's run differ from what it fed the other domains
  (simulating a corrupted party behaving inconsistently across domains)
  makes `MultiBitsConsCheck` correctly report a `MISMATCH` for that
  domain, while the untouched domain's check still passes — confirming
  the check actually detects inconsistency rather than trivially passing.
- The bitness check (`xorbits.mpc`'s and `multibits_{small,large}.mpc`'s
  `open(x*(1-x))`) was confirmed to abort the VM (nonzero exit, all
  parties) when a party's raw input file contains a non-bit value.

| N | q (bits) | t (bits) | n (MultiBits) | kappa | Q (bits) | result |
|---|---|---|---|---|---|---|
| 3 | 43 | 23 | 3 | 16 | 78 | PASS |
| 3 | 43 | 23 | 5 | 40 | 126 | PASS |
| 5 | 43 | 23 | 4 | 24 | 94 | PASS |
| 3 | 43 | 23 | 3 | 16 (t domain corrupted) | 78 | correctly FAILs on domain `t` only |

## Known limitations / natural next steps

- **Performance.** The per-bit bitness check and the fact that `Q` must be
  exponentially larger than `q`/`t` (hence arithmetic there is on a much
  bigger prime) make this considerably more expensive than the online
  phase — expected, since this is genuinely doing more cryptographic work
  (this is exactly the cost the paper's `CheckedInput`/FLIOP batching is
  designed to amortize away; that optimization isn't implemented here).
- **`Compare`** is still needed to turn MultiBits into the actual
  `modconv1-preproc` mask/corrections, as noted above.
- **More than two similar-size moduli / `ModConv2`'s preprocessing**
  would reuse this same machinery (`multibits_large.mpc` already accepts
  an arbitrary list of small domains checked against one `Q`), but hasn't
  been tested beyond `(q, t)`.
